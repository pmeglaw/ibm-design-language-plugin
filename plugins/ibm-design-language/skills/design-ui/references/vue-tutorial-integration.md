## Vue tutorial: identity, slots and verified accessibility

The [Vue tutorial](https://carbondesignsystem.com/developing/vue-tutorial/overview/) is community-maintained and uses Vue2-era Vue.use/new Vue, Vue Router, Options API, legacy slot syntax, Carbon Vue/icons and carbon-components Sass. Do not combine its registration/bootstrap with the framework page's Vue3 createApp fragment. Check installed Vue/Carbon Vue/router/Apollo compatibility, component props/events/slots, and existing bundler configuration. [Vue CLI documentation](https://cli.vuejs.org/guide/mode-and-env.html) identifies CLI maintenance mode and current new-project tooling; that is not authorization to migrate an existing app. SASS_PATH and legacy tilde/global imports are toolchain-specific; verify real imports/configuration rather than installing a different CLI/loader or changing package managers. The VS Code snippets are optional editor preferences, not part of Carbon behavior.

Step1's skip link href='#main-content' does not match id='#main-content': the fragment seeks the ID main-content without the leading hash. A narrow jsdom check confirms no matching target. Use a unique correct ID and verify keyboard focus/scroll after activation and route changes; ID lookup alone does not prove focus behavior. Maintain one persistent shell/content/router outlet, active route, unsaved-edit fences and responsive navigation. The source alternates src/view and src/views; preserve the actual directory. Verify supported Carbon Vue to/router-link composition and real anchor markup. Names for notification/account/switcher actions require implemented destinations/panels; tutorial labels do not supply them. Its formatting-only ci-check and comments about missing format/offline scripts do not establish behavioral tests or authority to alter existing tooling.

Step2's legacy grid flag/classes must match the stylesheet and actual grid implementation; installing @carbon/grid alone does not activate behavior or make v10 Sass recipes v11-compatible. Check nesting, breakpoint spans/gutters and long-content overflow. Broad unscoped style blocks and copied cds selectors affect other instances; keep overrides narrowly owned and review them on upgrades. Distinct navigation names depend on actual rendered breadcrumb/tabs semantics. Tokens for type, theme and line height do not dictate heading levels or justify body copy styled as a heading. The full-width pseudo-element must be checked for stacking, pointer coverage and overflow rather than assumed harmless. Preserve brand roles and loaded fonts.

Step3's VUE_APP_GITHUB_PERSONAL_ACCESS_TOKEN is embedded in client output even when .env.local is ignored by Git. [Vue CLI's environment guide](https://cli.vuejs.org/guide/mode-and-env.html#environment-variables) explicitly describes this exposure. Do not copy that credential pattern; use an established authorized server boundary or the application's approved identity model. No real token, login or live request is needed for this audit. The shown createProvider import disagrees with the following generated-file explanation; inspect the actual plugin-generated module/exports. A wsEndpoint comment says null while code reads an environment variable: determine actual supported transport/authentication requirements rather than treating comment or undefined value as a successful connection.

The GraphQL first75 query is bounded, not all repositories. This tutorial correctly supplies loaded rows.length for its client pagination total, unlike the Angular example; do not introduce server totalCount while slicing only loaded nodes. Its pageSize/pageStart/page initialize to0 and rely on an initial Carbon pagination event. Exact-expression checking confirms slice(0,0) returns no rows; the installed component's initial event behavior is unverified. Initialize/coordinate a real supported state, test first load, page-size changes, clamping, filtering, refresh and empty/failure states. Define the application policy for selection and expansion across pages rather than clearing every record indiscriminately.

The tutorial explains that row-index keys reuse expansion state across different records. Preserve stable record IDs through the computed table mapping and key rows by actual identity. The displayed mapping drops the ID before its v-for: adding row.id in the template without retaining it does not solve the issue. Cell keys should describe stable column identity where ordering can change. Computed data caches reactive dependencies, not arbitrary nonreactive state. Keep raw dates/counts for sorting, format separately and preserve original descriptions. The cell discriminator !cell.url throws for null/undefined, confirmed with exact-expression probes; use an explicit validated cell representation rather than guessing from one property. Validate nullable GraphQL structures and external URLs. Raw response interpolation/console.dir are teaching diagnostics, not permission to expose office records.

Loading skeletons and $apollo.loading do not establish an error/retry/partial-data path. Use the installed Apollo integration's supported query-specific state/error policy, lifecycle cleanup and stale-response protection; aggregate loading may reflect more than the intended request. Check empty results, rate limits, cancellation, invalid data and accessible status while preserving useful content. Avoid inventing Vue3 APIs for the tutorial's Vue2 target or copying deprecated Query/plugin recipes without verifying current versions.

Step4's slots/props/dynamic icon component illustrate reusable composition, but icon objects/created Object.assign, attribute fallthrough and scoped styling must match the selected Vue version. Icons are distinct from pictograms; a historical future-support note is not current asset availability. Use semantics appropriate to independently reusable content: [WAI-ARIA's article role](https://www.w3.org/TR/wai-aria-1.2/#article) has no universal accessible-name requirement. Do not replace an appropriate article solely because the tutorial says every article requires a label. A div may still fit a card that isn't independent content. Choose heading levels, useful grouping and optional names based on actual structure.

The tutorial also says an off-screen skip-link contrast violation can be ignored. Inspect its real focus state: a link revealed to sighted keyboard users needs readable text/contrast and visible focus. The [WCAG contrast exemption](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) for content not visible to anyone does not excuse a visibly focused link. Record whether a finding is a hidden-state artifact or an actual focus-state failure; don't blanket-ignore a scanner. Its splitHeading helper emphasizes the last space-separated word, not always the third, and needs safe optional/localized input. Verify responsive borders/order/long text and loaded icons rather than treating a screenshot or DAP run as complete conformance.

Step5's granular Sass and static build require measured output plus equivalent state/theme coverage. Its Cloud Foundry login/push recipe has the historical IBM support limits documented above; don't create accounts or deploy to it. A runtime manifest variable cannot alter an already built client bundle or conceal its token. Confirm actual production mode/output/base paths/route refresh and authorized hosting. Publication/PR approval labels prove only their underlying checks.
