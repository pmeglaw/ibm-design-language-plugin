## Web Components tutorial: registration, templates and application ownership

The [Web Components tutorial](https://carbondesignsystem.com/developing/web-components-tutorial/overview/) teaches a vanilla Vite multipage application, per-component registration, Sass, native templates/events and deployment. Its six raw source pages are reviewed; React-hosted previews and malformed prior-step links are not evidence for the Web Components implementation. Verify the actual installed @carbon/web-components/@carbon/styles versions, import entrypoints and custom-element definitions. Pnpm is this tutorial's choice, not an intrinsic create-vite requirement or authorization to switch an existing repository. Do not mount duplicated production shells because the educational example copies index.html to repositories.html; use the app's existing routing/template ownership and full-navigation policy.

Step1's reset import alone does not prove IBM Plex font assets loaded. Verify emitted font declarations and actual network/computed loaded face. Theme CSS and JavaScript must agree: matchMedia('prefers-color-scheme') is not a valid feature query, and testing the MediaQueryList object rather than .matches always treats it as truthy. Use a supported '(prefers-color-scheme: dark)' query with .matches, and a change listener when application state must follow OS changes. [MDN matchMedia](https://developer.mozilla.org/en-US/docs/Web/API/Window/matchMedia) describes these distinct checks. The later CSS system-default mode can respond without a JavaScript listener; verify explicit light/dark precedence, persisted choices, header inverse theme and portals rather than assuming the example handles them all.

Static HTML does not evaluate collapse-mode='${SIDE_NAV_COLLAPSE_MODE.RESPONSIVE}': bind a supported actual value/property after checking the implementation. Native custom-element attributes, Boolean presence, properties, event detail, slots and shadow boundaries are not React props; validate names/casing and event composition. Header panel-id relationships and the app's one-open-panel click coordinator need keyboard/Escape/focus/close-state checks; click handlers alone do not establish all interactions. Keep real targets/actions/labels and skip-link focus, responsive menu availability, scroll containers and320px/zoom/long-content behavior. The app's100vh/overflow-hidden/main-scroll setup requires actual visibility/focus tests, not a claim that the button disappeared only because of spacing. CSS-mask icons need loaded assets, contrast and appropriate decoration semantics; their parent control owns its accessible name.

Step2 shows cds-grid/cds-column and attribute span/start syntax: check those in the selected package before using or rejecting them. The source is evidence of a documented example, not an installed API proof. Grid Sass and custom-element registrations are separate dependencies. Preserve4/8/16 breakpoint context, nesting and offsets; don't carry React object props into HTML. A narrow styles1.116.0/Sass1.105.0 probe confirms breakpoint-up(md) and breakpoint(md) both compile to min42rem; do not invent a failure because the alias differs from another page. Likewise border-subtle and border-subtle-01 both compile, but the generic CSS variable lacks the numbered fallback; correct rendered values depend on actual layer/theme definitions.

The Design tab points to panel-design, but its displayed panel example omits that wrapper/ID; a synthetic target check finds it unresolved. Provide unique targets and actual tabpanel labeling, selection/hidden state and keyboard behavior across all tabs. Inspect shadow-to-light DOM associations and actual registration instead of assuming ARIA on a host fixes them. The tutorial's noTrailingSlash/itemsPerPageText spellings need verified Web Components attribute/property mappings, not guesses from React. Keep semantic heading structure and body type roles; check image sizing rather than asserting max-width prevents every overflow. Template insertion instructions place templates after the body and sometimes name index.html while editing the repository page: use valid actual document structure and page-local ownership.

Step2/3 fill cells through innerHTML and construct href attributes by string interpolation from external API values. [MDN innerHTML guidance](https://developer.mozilla.org/en-US/docs/Web/API/Element/innerHTML#security_considerations) identifies this as an injection sink. Prefer textContent for plain names/descriptions/counts and DOM-created links with validated permitted URLs; omit absent homepage links. If rich HTML is an actual authorized requirement, use the application's reviewed sanitization/trusted-content mechanism. A jsdom probe shows an external-looking img/onerror string becomes markup/event attributes with innerHTML and stays text with textContent; this is parsing evidence, not live exploit or browser execution proof. Custom-element upgrade and shadow encapsulation do not sanitize light-DOM data. Map known fields to known template nodes; handle missing nodes/null fields instead of dereferencing any interpolated key selector.

Step3's GraphQL introduction contradicts its actual REST Octokit request. per_page75 is a bounded set, not all repositories. Preserve raw dates/counts/IDs before formatting and define stable record expansion/selection identity. The displayed async function lacks rejection handling, cancellation/stale-response protection and an accessible empty/error/retry path; failures can strand the skeleton. replaceSkeleton is a one-time structural replacement, not a general refresh model. Table replacement loses DOM focus/listeners/expansion unless coordinated; verify required focus retention and attach/clean handlers through supported lifecycle ownership.

Client pagination filters the fetched dataset; it does not load new API records despite the source's 'new data being loaded' wording. Verify actual cds event names/detail fields and synchronize page/size/offset/total as one coherent state. Changing size alone can leave an obsolete offset: synthetic offset70/size50 on75rows yields only5rows. Actual component event order remains unverified. Clamp/reset per product policy after filtering/refetch and avoid duplicate listeners. setTimeout10 is not a definition/render-readiness guarantee; use actual lifecycle/update completion where needed, and do not assume a framework-specific onChange prop applies to these native events.

Step4 uses HTML templates rather than creating a reusable custom element. BEM naming organizes ownership but does not encapsulate styles. Its fixed300px card height, nth-of-type rules, row-reverse and pictogram masks need long-content/RTL/responsive checks. Extra/fewer placeholders can mismatch infoCardDetails[index]; validate scope/data before destructuring, preserve semantic heading/group roles and write plain messages with textContent. Replacing nodes requires deliberate interaction/focus/state ownership. Verify loaded approved pictograms and purposeful visual emphasis without elevating demo content or palette styles to brand authority.

Step5's lint configurations are examples, not a complete accessibility/RTL guarantee or permission to add tooling/Prettier/dependencies. Match installed plugin/config versions and required project checks; run bounded autofixes only within scope. Its ESLint example imports @eslint/js without explicitly listing it in the install command: check the actual dependency graph rather than claiming it is absent or relying on a transitive package. Stylelint token checks cannot prove computed contrast or interaction. Vite configuration needs actual fileURLToPath imports and both HTML entrypoints. [Vite's deployment guide](https://vite.dev/guide/static-deploy.html#github-pages) ties base to deployed URL: root/custom domain versus repository path, not personal versus organization ownership. Verify asset URLs and route refresh on the production build; a package homepage string is not a complete Vite base setting. gh-pages scripts publish and require explicit authorization.

The CDN variant pins v2.17.0 but omits grid registration from its removal/addition lists even though main.js imported it earlier. Determine whether bundled registration remains and whether the chosen CDN has a supported grid module before claiming node_modules independence. Mixing npm and CDN versions can cause duplicate definitions/API mismatches; pin one compatible registration source and test readiness/network failure/CSP/assets. Do not change transport or replace imports merely to satisfy the tutorial. No actual custom-element package runtime, CDN access, tutorial build, hosted render, live API, keyboard/focus or AT evaluation occurred in this audit.
