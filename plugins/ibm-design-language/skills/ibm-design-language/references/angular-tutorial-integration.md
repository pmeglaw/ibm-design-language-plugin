## Angular tutorial: community implementation and application state

The [Angular tutorial](https://carbondesignsystem.com/developing/angular-tutorial/overview/) is community-maintained and teaches NgModules, Carbon Angular models/templates, routing and content projection. Its seven source pages specify Angular CLI8.x while showing an unpinned global CLI install, legacy carbon-components imports/ibm selectors and Apollo Angular v1. Verify the installed Angular, Carbon Angular, Sass and GraphQL compatibility before adapting it; do not install the latest global CLI expecting that historical recipe to work. Preserve the user's existing standalone or module architecture, tooling and package manager. A tutorial's nested generated app, lint autofix, scaffold-test deletion, global/sudo install and publication commands are not authorization for those changes in a governed repository.

Step1's icon imports name three icons but registerAll only includes Notification20 while the template uses all three. Register actual assets in the correct provider/module scope and verify current icon paths; don't invent core React-equivalent APIs. The app.modules.ts/header paths and home-page.module.ts versus home.module import are inconsistent. Use actual generated files rather than making duplicates to satisfy prose. Generic title='action' cannot convey notification/account/switcher purpose; meaningful names need matching actions. HostBinding a header class is not proof content clears the header. Retain one persistent shell/main outlet, working skip target, mobile navigation and client routing. Hash routing is a hosting choice, not universal product navigation policy; confirm Angular-specific route bindings and refresh/deep-link handling.

Step2's initial row labels its second span8 while binding lg7;7+1offset+7 fills15, not the claimed16. Later examples bind lg8. Reconcile intended spans, available breakpoint columns and nesting in the installed implementation. Its legacy grid-columns-16 flag must precede relevant legacy Sass imports; don't copy it into v11 React CSS Grid setup. Global forced header navigation display and full-width/row gutter overrides need rendered320px/desktop checks; they can defeat responsive behavior. Inspect actual Angular breadcrumb/tab markup and distinct names rather than asserting all framework implementations use identical nav roles. Keep semantic headings, decorative-art treatment and real link/action destinations independent of visual type styling. Legacy ui-01/ui-03/layout/productive tokens and carbon-- prefixed mixins require the version's mapping, approved semantic aliases and compilation; do not translate a palette name into a new hard-coded brand color.

Step3 embeds githubPersonalAccessToken in environment.ts and uses it in a browser authorization header. Do not reproduce that in a production application. [Angular's environment documentation](https://angular.dev/tools/cli/environments) confirms these files become public client output. Ignoring a source file, using a build/manifest variable or minifying JavaScript does not conceal a shipped credential. Use an established authorized server-side boundary with least privilege and no secret logging; do not create tokens or change authentication merely to run this audit. Source environments directory paths disagree and step5's .env.local note comes from a different tutorial.

The GraphQL query requests first75 nodes but totalCount can be larger; the sample sets totalDataLength to that larger total while slicing only fetched nodes. A synthetic exact-expression probe with75nodes/total120/pageLength10 yields5rows on page8 and0 on pages9–12 while advertising12pages. Choose truthful loaded-row totals for client pagination or implement actual cursor/server fetching with stable order, page state and request ownership. Do not equate first75 with all data. Define page-size changes, clamping, filter/search order, refresh selection and empty results. Carbon Angular TableModel/TableItem/header/templateRef contracts are distinct from React DataTable render props: preserve descriptions/stable identity and raw values for sorting, then format dates/counts for the locale. Validate external links and null/malformed records before deriving cells.

GraphQL's no-errors assertion does not guarantee non-null organization/nodes; honor actual schema and error policy. The displayed subscribe success callback checks response.error but has no Observable error callback/teardown and leaves skeleton true in its error branch. Error policy/property names must match installed Apollo, with transport and GraphQL failures, partial data, retry, loading completion and stale-response protection tested. An 'error!' single-cell row under six headers is not a complete accessible error presentation. Use the existing data layer, stop/dispose active subscriptions on teardown as appropriate, and verify view-query timing before passing templateRef. @ViewChild(...,null), untyped any and compiler workaround snippets are historical examples, not a reason to weaken current typechecking or suppress unrelated diagnostics.

Step4's inputs/content projection demonstrate reuse, but hard-coded items[0..2] and ngOnInit-only splitHeading do not support arbitrary data or later input updates. [Angular lifecycle guidance](https://angular.dev/guide/components/lifecycle) distinguishes initialization from subsequent input changes. Derive current structured content through the project's supported input/change mechanism; don't prescribe modern signal APIs to Angular8 without a migration. The split helper pops the last word, despite its third-word comment; support localized emphasis deliberately. Check module exports/imports, JSON resolution, projected icon semantics and encapsulated styles against actual package support. Ellipsis-bearing snippets are insertion instructions, not standalone compilable SCSS/JSON. Verify wrapping, long content, logical borders, breakpoint changes and heading hierarchy in rendered output; source tokens and diagrams do not prove accessibility.

Step5 mixes Angular CLI with Create React App production-build prose, dist/build directories and React token links; inspect the actual build script, angular.json output path and production configuration. Granular Sass imports must include every used state/dependency and remain equivalent in themes/responsive behavior; measure output rather than assuming smaller means correct. Its IBM Cloud Foundry deployment is historical: [IBM's deprecation notice](https://cloud.ibm.com/docs/messages-for-rabbitmq?topic=messages-for-rabbitmq-getting-started#create-a-cloud-foundry-alias-for-the-database-service) states new apps ceased November2022 and support ended June2023. Do not present that login/push recipe as a currently supported deployment path. A runtime manifest variable also cannot retroactively secure a prebuilt client token. Verify the authorized current hosting model; do not provision, authenticate, delete build directories, push or deploy from tutorial instructions. Wrapping up mistakenly links the Vue PR list. Tests/approved labels demonstrate only their actual checks, not all engineering requirements. No Angular tutorial installation/build, live GraphQL, images/preview, browser or AT verification occurred in this audit.
