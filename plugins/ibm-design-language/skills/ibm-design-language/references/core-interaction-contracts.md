# Core interaction contracts

## Tree view

Use a tree for a meaningful multilevel hierarchy, such as folders and files. Use shell navigation for product architecture, Accordion for a shallow content disclosure and DataTable for horizontally comparable attributes. A visual branch label is not automatically an HTML heading. Distinguish expansion, focused node, selected nodes and active/current destination; expanding a parent does not mean selecting its descendants or navigating to it.

- Document the selection model and default action. Expected single entry stop lands on selected/first node; Up/Down traverse visible nodes, Right opens or enters a branch, Left closes or reaches its parent, Home/End reach visible endpoints and Enter activates. Carbon Accessibility also describes Space selection. Keep collapsed descendants out of traversal and reading. Selection must not silently trigger destructive work merely because focus moves.
- A named tree contains treeitems and named group subtrees, with unique stable IDs, parent expanded state and consistent selection/current semantics. Leaf nodes should not claim expansion. For virtualized/partially loaded data, establish hierarchy/position metadata, async loading/errors, retained selection and focus recovery rather than assuming DOM-derived structure remains sufficient.
- Inspected `@carbon/react@1.117.0` TreeView separates selected IDs and active ID. enable-treeview-controllable makes selected/active values controllable and onSelect(nextIds)/onActivate(nextId) value callbacks. Without that flag, selected/active initialize internal state and legacy onSelect receives (event, node), with activeNodeId in ordinary single selection. TreeNode expansion similarly changes from legacy onToggle(event, nodeDetails) to onToggle(nextBoolean), with isExpanded/defaultIsExpanded under the flag. Node-level onSelect remains an event/details callback. Verify the exact flag and types before wiring persistence; do not reuse a legacy callback signature in controlled mode.
- Root arrows/Home/End manage roving tabindex and TreeWalker skips disabled/hidden subtrees. The initial/children-change effect assigns tabindex=0 to the first enabled node rather than explicitly the preselected node. Left/Right movement focuses nodes without the same root tabindex reset path. Test initial selected entry, reentry, dynamic children and reverse traversal instead of claiming the documented single-stop behavior from source alone.
- Enter on a branch both toggles expansion and calls selection; Space calls selection without that branch toggle. A link node key handler also invokes a DOM click before its direct handleClick call, so callback counts and navigation must be checked for keyboard activation. Prevent duplicate side effects without disabling ordinary browser navigation. Caret pointer click stops propagation and avoids link navigation, preserving expansion as a separate action.
- Multiselect only toggles membership for Ctrl/Meta selection in the inspected handler; ordinary selection replaces the array. Home/End and Ctrl+A handling can concatenate IDs and trigger selection callbacks; Ctrl+A's branch is not explicitly gated by multiselect. Verify single-select cardinality, duplicates, shortcut prevention, platform modifier differences and select-all scope. No typeahead handler was found in the inspected TreeView/TreeNode source; provide an appropriate supported solution when large-tree access requires it rather than promising APG functionality automatically.
- Ordinary nodes are li treeitems with selected state; href variants put treeitem on an anchor inside a role=none li, use aria-current=page and omit aria-selected. Inspected href leaves still receive aria-expanded even without children. Verify announced role/current/leaf semantics and disabled behavior, especially with truncation help and nested link content. Node props active/selected/depth/onTreeSelect are deprecated internal overrides; prefer the owning tree contract.
- Usage asks a collapsed parent to inherit the visual selection indicator when a chosen descendant disappears; inspected isSelected only tests inclusion of that node's ID. Preserve hidden selection/context deliberately and verify supported styling; do not add the parent to committed selected IDs merely to imitate an indicator.

Documented sizes are 32px small and 24px extra small, labels body-compact-01, nodes stacked without inter-node gaps. Text-only branch indentation grows by 16px per level and leaf labels add a 24px offset; icon branches grow by 24px per level and preserve corresponding leaf alignment. Use logical inline offsets for RTL and inspect installed CSS rather than translating each example into fixed left padding. Maintain consistent optional icons, semantic layer/hover/selected/focus roles and a visible selection indicator. Deep nesting and small rows must retain usable targets and label access.

Usage suggests a browser tooltip for truncated labels; inspected source instead detects ellipsis and wraps labels in IconButton help. Verify extra stops, nested controls in link variants, full-name exposure, resize/locale changes and touch/keyboard access. Native title alone does not establish those requirements. Do not force user-generated file names into sentence case or shorten meaningful suffixes without another full-text route.

Verify branch/leaf roles, selected versus active/focused state, both flag modes and callback signatures/counts, native link destination, single/multiple selection/cardinality, disabled/hidden traversal, arrows/Home/End/Enter/Space and modifiers, initial/reentry focus, controlled updates, selection retained after collapse, async removal/load/error, truncation/help, deep/long/translated labels, responsive/RTL/zoom and actual contrast. No Tree view runtime/AT pass was performed.

Sources: [Usage](https://carbondesignsystem.com/components/tree-view/usage/), [Style](https://carbondesignsystem.com/components/tree-view/style/), [Code](https://carbondesignsystem.com/components/tree-view/code/), [Accessibility](https://carbondesignsystem.com/components/tree-view/accessibility/). Four source tabs reviewed 2026-09-29 at website commit `d8783ad2ae3b5e59c58f58311491f8a2c4e62631`; images/demos and linked internal IBM references remain uninspected. Its full keyboard model is not a claim about every Carbon release.

## Tile

Choose the interaction before the visual treatment: base Tile is a noninteractive container whose child actions have their own targets; ClickableTile navigates through a whole-tile target; RadioTile chooses one option in a group; SelectableTile independently toggles multiple choices; ExpandableTile reveals additional content. A complex card pattern may need product-specific guidance beyond Core Tile.

- Use a real destination for navigation, meaningful names and normal browser link behavior. Keep other actions out of the clickable surface. Usage permits separate inner CTAs in selectable tiles, but Accessibility forbids nested controls and inspected RadioTile/SelectableTile explicitly reject interactive children. Compose a base container with distinct controls or a separately supported structure; do not copy the conflicting example into a nested anchor/button/label.
- RadioTile uses a native radio input and associated label. TileGroup provides a fieldset/legend, shared name and selected value. Native radio group Tab/arrow behavior takes precedence over a generic instruction to Tab through every tile. RadioTile additionally handles Enter/Space through onChange(value, name, event). TileGroup supports defaultSelected/valueSelected and only notifies when the value changes; inspect focus/selection and callback counts for initial/no selection, disabled choices and reverse entry.
- SelectableTile in the inspected version is a div with role=checkbox, aria-checked and its own tab stop, not a native submitted checkbox. It tracks local selection synchronized from selected, calls onChange(event, newSelected, id), and toggles on click or Enter/Space. name/value are deprecated unused selection props: serialize application state explicitly. Disabled removes its ordinary handlers/tab stop, but inspect rendered disabled semantics rather than assuming native checkbox behavior.
- ExpandableTile detects interactive descendants/decorators. With them it uses a separate named native chevron button; without them the whole surface becomes a native button. It expects the first two child entries as above/below content. Expanded state is local and synchronized from expanded, while onClick is composed with the toggle; passing expanded does not by itself establish fully app-controlled or vetoable behavior. Annotate who owns the state and test any confirmation flow.
- Expansion supplies aria-expanded/controls, measures collapsed height and observes the above-content resize. Inspected markup does not explicitly hide/inert below-content descendants when collapsed. Check CSS visibility, accessibility exposure and keyboard traversal rather than equating visual max-height clipping with exclusion. Verify collapsed descendants, async content, resizing, scroll position and focus after collapse. Usage's Shift+Tab instruction accidentally says forward; normal reverse traversal applies.
- Documented minimum tile size is 128px wide by 64px high with 16px padding. These are starting geometry, not permission to crop longer content. Base body-compact-01 can be composed with an appropriate heading hierarchy. Keep related tiles consistent; masonry or variable dimensions require meaningful reading and DOM order. Informative media needs useful alternatives; decorative media does not duplicate prose.
- Tile Style's breakpoint table lists 576/768/992/1200/1600 values that conflict with Carbon's current 2x Grid guidance. Do not encode that table as global Carbon breakpoints. Verify the installed Grid and product layout contract. Test content fit at narrow widths and zoom rather than enforcing a fixed aspect ratio regardless of text.
- Preserve contextual layer, layer-hover, text-primary, focus and selected border roles. Ordinary tiles do not gain arbitrary shadows. AI tile aura/shadow/rounded treatments are documented variant exceptions, not authority to alter every tile. Explainability is a separate action; inspected clickable/selectable decorators can be siblings of the target.

Selected `@carbon/react@1.117.0` source inspected: ClickableTile delegates to Link; without href its key handler calls onClick for Enter/Space, whereas navigation relies on link activation. Its key handler itself lacks a disabled check; verify actual disabled Link semantics and supplied overrides. Flags enable-v12-tile-default-icons and enable-v12-tile-radio-icons control default navigation/disabled and radio glyphs. Code also documents enable-tile-contrast; verify installed flag/theme behavior before applying it. light/slug props are deprecated in favor of Layer/decorator. No migration is implied by a website example.

Verify valid nesting and names, actual destination, radio versus checkbox semantics, callback counts and serialization, controlled rerenders, disabled state, separate decorator/help actions, expansion/collapsed descendants, long/translated content, grid/DOM order, media alternatives, keyboard/touch/RTL/zoom and theme contrast. No Tile runtime/AT pass was performed.

## Tabs

Organize distinct related panels within the same context. Use ContentSwitcher for alternate views of the same content, ProgressIndicator for sequential steps and navigation for other routes. Do not hide information in separate tabs when users must compare it simultaneously. Preserve entered values and meaningful selected-tab state while users work elsewhere.

- Annotate automatic versus manual activation. Automatic arrow focus also selects and displays the panel, suitable when content is available without noticeable latency. Manual arrows move focus while Enter/Space commits selection. Keep pending/error states scoped to the panel and prevent stale asynchronous responses from replacing newer content. Focus traversal must not silently trigger expensive mutations.
- Use named tablist, tab buttons with selected state, unique controls/labelledby panel relationships and one tablist entry stop. Horizontal arrows wrap; vertical uses Up/Down. Home/End can reach endpoints. Tab proceeds to panel content or a focusable panel when meaningful initial text has no focusable entry; inactive panels must exclude descendants from traversal. A selected tab is not the same as a focused unselected manual tab.
- Horizontal tabs scroll instead of wrapping, with keyboard focus kept visible. Icon-only tabs need names and hover/focus help; vertical truncated names need keyboard/touch access to full text. Keep concise translated labels meaningful rather than imposing a three-word cap. Overflow scroll arrows are pointer aids, not extra required keyboard stops.
- Line tabs use auto-width and align the first label with the surrounding text; contained tabs attach to a panel using the same contextual layer. Grid-aware contained tabs are equal-width and return to auto-width at smaller breakpoints. Source recommends four or fewer for grid alignment in one section but up to eight in another: use actual label fit and responsive behavior rather than treating either as an API limit. Secondary labels belong to grid-aware contained tabs, not every variant.
- Documented horizontal height is 40px, icon-only variants 40/48px and vertical 64px. Line selected border is bottom 2px; contained top 2px; vertical leading 3px. Selected labels use heading-compact-01, unselected body-compact-01 and secondary label-01. Preserve semantic layer/border/focus roles and RTL. Default trailing-rule extension is application composition, not built-in functionality.
- Vertical is local content organization, not a replacement for shell navigation. Source describes 4/2 grid columns and scrolling contained tabs at small breakpoints, despite the earlier statement that vertical always stacks. Verify the implemented responsive composition; stable panel height must not create excessive blank space or clipped long content.
- Dismissible tabs suit user-created/retrievable contexts. Warn only for actual data loss/unsaved edits, keep a way to create a tab after the last closes, and move focus to a logical successor. Closing a view must not accidentally delete its underlying record.

Selected `@carbon/react@1.117.0` source inspected: Tabs uses zero-based selectedIndex/defaultSelectedIndex and `onChange({ selectedIndex })`; TabList owns `activation="automatic" | "manual"`. Horizontal/vertical handlers wrap enabled tabs, support Home/End and keep focused tabs visible. Scroll controls are aria-hidden with tabindex=-1. Preserve tab/panel ordering when dynamically adding/removing entries.

The API spells `dismissable`, with `onTabCloseRequest(index)` required; it requests application removal rather than automatically deleting data. Delete invokes that request; close-icon labels interpolate only string children, so complex/localized labels need naming checks. Focus-after-close relies on current DOM sibling positions and must be verified with disabled/dynamic tabs and deferred confirmation. Ordinary TabPanel renders hidden/label relationships but does not assign a focusable tabindex automatically: compose it when the panel's initial meaningful content needs an entry stop. Vertical TabPanels temporarily measure hidden panels to set height; verify async/long-content responsiveness. The dismissible icon can lead despite Usage's “icons always right” statement; inspect the specific modifier rather than globally overriding it.

Verify automatic/manual focus versus selection, named relationships, hidden descendants, Tab/arrows/Home/End/Enter/Space/Delete, all-disabled/removed selection, asynchronous errors, close veto/successor, state preservation, long/translated labels, scrolling/RTL/zoom and actual theme contrast. No Tabs runtime/AT pass was performed.

Four-tab public source text reviewed 2026-09-29 at website commit `d8783ad2ae3b5e59c58f58311491f8a2c4e62631`; images/demos uninspected. ## Accordion

Use progressive disclosure for optional content users may not need. If most users must read every section, visible page headings avoid repeated opening and hidden essential information.

- Panels are collapsed by default; several panels may remain open independently. Do not introduce an exclusive single-open rule without a task-specific reason.
- Each header is a keyboard stop; Enter/Space toggles it. Expanded interactive content participates in normal tab order. Collapsed content must not remain keyboard reachable.
- Give the header button its name, `aria-expanded`, and `aria-controls` pointing to a unique panel ID. If titles structure the page, annotate and implement appropriate heading levels: Carbon does not make them headings by default. Preserve valid semantic grouping rather than putting a solitary accordion in an unnecessary list.
- Prefer page/whole-accordion vertical scrolling to independent panel scroll regions. Content must fit its available width without horizontal scrolling.
- Small/medium/large header heights are 32/40/48px. Use the documented body type and spacing; forms may use more of the panel width than copy. Verify installed behavior when adapting narrow side panels.
- Usage prefers a trailing chevron for text alignment; Accessibility recommends a leading chevron for low-vision proximity. Choose the supported variant deliberately and document the tradeoff. Neither is a universal direction rule; check RTL.
- The Style prose and margin table disagree at exactly 640px. Inspect the target implementation before encoding a breakpoint. A suspicious token-table entry is a verification question, not permission to change semantic colors.

Verify independent expansion, initial state, heading outline, unique relationships, collapsed-content focus exclusion, long content, narrow layout and the chosen chevron variant.

Installed-source receipt, `@carbon/react@1.117.0`: AccordionItem declares `renderToggle` and deprecates `renderExpando`; it passes the toggle its button type, class, disabled state, click handler, expanded/controls attributes and children. Where a semantic title heading is needed, a supported custom toggle can place the complete button inside an appropriate heading while forwarding that contract. Putting an h3 inside `title` instead puts the heading inside the default button; it does not establish the [APG heading-containing-button structure](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/). Verify actual accessible heading exposure and layout after customization. This receipt is source inspection, not a rendered pass or a rule for every Carbon version.

## Breadcrumb

Use as secondary navigation in a sufficiently deep hierarchy. It supplements primary navigation. Use a progress indicator for a multistep process, not a breadcrumb.

- Public Usage supports location-based hierarchy and dynamically generated path-based trails. Choose a consistent model. A history trail and an ancestor trail have different meanings; do not silently mix them. The earlier preview summary's hierarchy-only shorthand is incomplete for this public source.
- Place below shell navigation and above the page title. Medium is the default; small suits page headers, constrained space and smaller breakpoints. Small/medium text uses label-01/body-compact-01 respectively.
- Omit the current page by default when the page title already makes it clear. When needed, put it last as noninteractive text; ancestors are links. Tab/Shift+Tab traverses links and Enter activates them. Decorative separators have no action.
- Use a named navigation landmark and a semantic list. Give an overflow trigger a meaningful name and use the overflow menu's keyboard contract.
- Keep a single line. At ordinary widths preserve the first and last two links, moving intervening items into overflow. At the smallest widths Carbon allows overflow followed by one breadcrumb. Verify the particular responsive trail rather than insisting all three visible positions survive every width.

Verify real destinations, named navigation, current-page semantics, keyboard access to hidden ancestors, long labels, narrow widths and the chosen trail model. Destination content must become usable after activation; existence of a fragment ID or a clipped placeholder is insufficient. See [destination and outcome acceptance](practical-implementation-review.md#implement-destinations-and-outcomes-before-presentation).

Sources: [Usage](https://carbondesignsystem.com/components/breadcrumb/usage/), [Style](https://carbondesignsystem.com/components/breadcrumb/style/), [Code](https://carbondesignsystem.com/components/breadcrumb/code/), [Accessibility](https://carbondesignsystem.com/components/breadcrumb/accessibility/).

## Button

Use a button for an action and a link for navigation. Prefer native semantics. Keep page-level emphasis tied to the task; read-only pages can have no primary, while a temporary focused flow can have its own. See [composition](composition.md) for containers and [content design](content-design.md) for action meaning.

- Carbon secondary buttons accompany a primary for negative actions such as Cancel/Back; use tertiary or ghost for independent supporting actions. Do not infer priority solely from variant names. Avoid multiple high-emphasis buttons in one group.
- Group related actions. Two or three actions can be visible; more actions may need a meaningful menu or toolbar. Keep group sizes consistent and equalize related labeled-button widths to the longest label where the documented pattern applies. Recommended 16px spacing is a layout responsibility, not an automatic gap built into every button.
- Full-page left-aligned groups put the primary first; dialogs/wizards put it at the right. Vertically stacked groups put it on top. Apply logical alignment for RTL rather than copying physical left/right instructions blindly.
- Left-align labels and put a related icon after the label in LTR; mirror the whole arrangement in RTL. Use sentence case, usually verb+noun. Allow long or translated labels to wrap; do not truncate the action. Verify height, hit area and surrounding alignment with real content.
- Seven documented heights are 24/32/40/48 productive/48 expressive/64/80px. Productive text is 14px, expressive 16px; icons are normally 16px and expressive 20px. These design sizes do not prove seven matching exports or props in a target package.
- Icon-only controls need an accessible action name and a tooltip available on hover/focus, even for familiar icons. A decorative icon beside visible text must not duplicate the accessible name. Public guidance requires a visible label for danger buttons; do not turn a destructive action into an unnamed or icon-only danger button.
- Choose danger emphasis from the destructive task's importance. Preserve consequence disclosure and recovery appropriate to the action; styling is not a confirmation or safety mechanism.
- Enter/Space activates a focused native button. A toggle exposes its pressed state or a clear changing action label. Menu triggers inherit the menu contract, including expanded state and focus behavior.
- During an asynchronous action, show local progress and prevent duplicate submission. Handle completion and error, including restoring an available retry path. Disabling a button is not a status announcement; verify accessible feedback and focus when loading replaces the control.
- Generic Button prose says a dialog's primary typically takes focus. Apply the specific dialog/task contract instead of auto-focusing a destructive commit action. Initial focus must account for consequences, content reading and the installed modal behavior.
- Fluid/full-span, hanging and stacked-fluid examples carry production caveats. They may require an override; verify current installed capabilities and do not invent a `fluid` prop. The source also conflicts over tertiary buttons in fluid arrangements: favor the explicit tertiary restriction and inspect the actual chosen variant before extending it.

Verify action/destination semantics, hierarchy, keyboard activation, RTL, translated-label wrapping, names/tooltips, menu/toggle states, duplicate-submission prevention, failure recovery and target-package support. Include every enabled supporting action in [outcome acceptance](practical-implementation-review.md#implement-destinations-and-outcomes-before-presentation), and inspect long labels inside open nested regions rather than testing only the primary group. Check the full state/theme matrix; a Style table or static screenshot cannot prove rendered focus/contrast.

Sources: [Usage](https://carbondesignsystem.com/components/button/usage/), [Style](https://carbondesignsystem.com/components/button/style/), [Code](https://carbondesignsystem.com/components/button/code/), [Accessibility](https://carbondesignsystem.com/components/button/accessibility/).

## Checkbox

Use independent choices allowing none, one or many; use radio buttons for mutually exclusive choices. A toggle generally applies a setting immediately, while a checkbox often participates in a later form submission. State the actual commit behavior instead of relying on appearance.

- Each checkbox has an accessible label, even when visually omitted. The label and input both activate it. Use semantic grouping with a fieldset/legend where the options form a group; avoid redundant group labels when a containing group already provides the needed context.
- Tab/Shift+Tab visits individual controls and Space changes selection. Prefer vertical groups for scanning. In meaningful multicolumn sequences, reading, DOM and keyboard orders must agree; do not fix a CSS order problem with positive tabindex.
- A bulk parent selects or clears its child set. Compute unchecked when none are selected, checked when all are selected, and mixed when some are selected. Expose indeterminate state programmatically; changing one child updates the aggregate. Test empty sets and the scope of bulk actions rather than assuming the visible page is the entire collection.
- Keep labels concise and in sentence case; the source's three-word advice is a writing target, not a reason to remove necessary meaning or break translations. Wrap long labels, top-align the control, and preserve its label relationship; do not ellipsize.
- The glyph is 16px with an 8px label gap, but the clickable label/input region determines usability, not glyph dimensions alone. Preserve state-specific focus, disabled, read-only, error and warning roles and helper/error associations.
- Read-only is different from disabled. Native checkboxes have no `readonly` attribute: use the supported Carbon implementation or implement the complete no-change contract deliberately, including pointer/keyboard, state exposure and form behavior. Do not claim read-only semantics by adding an ineffective HTML attribute.
- AI labels may identify a whole group or individual suggestions; the documented mini label does not otherwise recolor checkbox tokens. Explanation access remains separate from changing the choice.

Verify labels/grouping, logical tab order, Space, parent/child aggregation, label wrapping, disabled/read-only behavior, validation and the true submission boundary.

Installed-source receipt, `@carbon/react@1.117.0`: Checkbox consumes `readOnly`, exposes `aria-readonly`, suppresses its change callback and prevents click default. It sets the input's native `indeterminate` property. Use supported props with coherent controlled state, and test pointer/keyboard plus form submission; this source read does not prove all browser/AT outcomes.

## Code snippet

Use read-only reusable text; editable code needs a different control. Inline snippets belong within prose and should stay on one line; single-line snippets accommodate long strings; multiline snippets can disclose more lines or scroll.

- Copy the original source string, preserving whitespace, newlines and syntax. Show success only after a successful clipboard operation; handle unavailable/denied clipboard access. Syntax highlighting must not alter what is copied.
- Copy controls have accessible names and tooltip/status feedback. Inline copy is itself a button; single-line snippets provide a separate keyboard stop for horizontal scrolling. Copy and Show more/less activate with Enter/Space; focus stays on the activating control when context does not change.
- Long single-line and terminal-command content can scroll horizontally. Multiline content may use Show more/less or vertical scrolling beyond nine lines. Verify keyboard scrolling and access to the full text without forcing the entire page to overflow.
- Show more/less describes the actual disclosure and preserves the full copy payload. Do not copy only the visible excerpt unless that is an explicit, clearly labeled different action.
- Use code-01 typography and contextual layer roles. The Usage page describes a legacy `light` field-01/field-02 mapping while Style uses contextual `$layer`; verify the installed version's prop and theme/layer behavior instead of combining these into an invented token rule.
- The Style table lists single-line height as `40 / 3` px/rem, an inconsistent conversion. At a 16px root, 40px is 2.5rem. Treat dimensions and typography tables as versioned design specifications; inspect implemented CSS before copying a contradictory number.
- Sample code in Code is example snippet content (including old React resolutions), not a recommended current app manifest or toolchain.

Verify exact clipboard payload, success/error feedback, focus retention, full-text reachability, expansion/collapse, keyboard scrolling, syntax contrast, nested themes and constrained widths. Match the Tab focus target to the actual rendered overflow owner; a focusable outer wrapper does not establish that its inner code scrolls by keyboard. For the inspected-version boundary and app-scoped integration choices, see [practical implementation review](practical-implementation-review.md#make-the-keyboard-focus-target-own-the-overflow).

Installed-source receipt, `@carbon/react@1.117.0`: CodeSnippet accepts `copyText`, `hideCopyButton` and collapsed/expanded row-count props. Its copy handler calls copy-to-clipboard without checking the returned outcome; Copy feedback is activated on click. If the task requires confirmed failure/success, the built-in feedback alone is insufficient. A deliberate integration can retain the CodeSnippet display/disclosure, hide its copy button, and use a separately named Carbon action that reports the actual clipboard result. Check the installed release before adopting this boundary. Minimum expanded rows and resize-observer logic can affect Show more behavior; test the actual line count instead of assuming a button's presence proves expansion works.

## Contained list

Use a compact collection with one group title and consistent row content, optionally including actions. Multiple comparison headers call for a structured list/table; extensive nesting or complex tooling needs a more suitable collection model.

- On-page is persistent in a card/sidebar/page; disclosed is temporary in a popover/disclosure. Span the available container width. Stacked on-page lists have 16px separation; disclosed lists are flush. Optional sticky headers need an opaque layer and must not obscure focused content.
- Use a semantic list with a title association. Noninteractive rows have no extra tab stop. Clickable rows and separate inline actions are independently keyboard reachable; do not nest a button/link inside another actionable button or make an inline action accidentally invoke its row action. Annotate row action intent because default appearance may not reveal clickability.
- The documented clickable-action variant uses buttons and Enter/Space. A navigation link must preserve native link behavior instead of inheriting a button action contract merely because it occupies a row.
- Rows can grow for concise multiline details; avoid paragraphs of prose inside each item. Preserve similar content structure and identify action targets accessibly. Decorative icons are not additional spoken labels; status icons need their status meaning.
- Default on-page row size is 48px; sizes include 32/40/48/64px. Disclosed guidance specifies 32px headers with 48px default rows. Style's Structure table conflicts with its Size table and Usage on header heights: verify the selected variant in installed CSS, not a global fixed-header rule copied from one table.
- Search/filter affordances may disclose in the header or remain below it. Provide field names, focus behavior and meaningful no-results recovery; a decorative search icon does not implement filtering.

Verify row versus inline-action activation, list/title semantics, labels, growth/scrolling, sticky-header focus visibility, search states and the selected variant's actual dimensions.

Sources: [Usage](https://carbondesignsystem.com/components/contained-list/usage/), [Style](https://carbondesignsystem.com/components/contained-list/style/), [Code](https://carbondesignsystem.com/components/contained-list/code/), [Accessibility](https://carbondesignsystem.com/components/contained-list/accessibility/).

## Content switcher

Use mutually exclusive alternate views or subsets of similar content, such as list/grid or All/Read/Unread. Use tabs for distinct areas and a toggle for a binary setting. Two views do not make a setting control appropriate.

- At least two options, exactly one selected. Choose the default from use and keep it consistent. Place above its content and align to content/grid; do not center it arbitrarily or flush it against a containing edge.
- Each text option has equal width based on the longest label or the selected grid columns. Use concise noun labels, not command verbs. Icon-only options have fixed square sizes and meaningful names/tooltips; do not mix text-only and icon-only options in one switcher. Responsive icons must still communicate view meanings.
- Keyboard uses one group tab stop and arrow navigation. Automatic activation synchronizes focus and selection; manual activation moves focus with arrows and commits with Enter/Space. Annotate the choice; update latency can make manual activation preferable.

- Heights are 32/40/48px; icon sizes 16/16/20px. Do not stretch an icon option beyond its square container. Long-label truncation guidance uses a browser tooltip; supply the full accessible name and keyboard/touch access to meaning rather than relying exclusively on `title`/hover.
- The Usage state table reverses the descriptions of selected and unselected. Its explicit default-selection prose and Accessibility `aria-selected` contract establish the intended state; verify code rather than reproducing the reversal.

## List

Use semantic `ul`/`ol` with `li` for related items. Ordered lists convey sequence or rank; unordered lists do not. The Usage ordered-list paragraph mistakenly says "without a specific order", contradicting its own variant description and sequential examples. Preserve the semantic distinction rather than copying that sentence.

- Lists are not themselves keyboard controls. Native links or actions within items retain their own names and keyboard behavior; do not add tab stops merely to make every item focusable.
- Productive list text uses body-01 (14px); expressive uses body-02 (16px). Default first-level unordered markers are en dashes and nested markers squares; ordered levels use numbers then letters. Nest with 16px indentation and preserve DOM hierarchy. Test actual list announcement when customizing markers; pseudo-elements are not universal assistive-technology proof.
- Stack items vertically. Separate list groups may share grid columns, but markers align with the content grid rather than disappearing into its gutter. Wrap long item text without truncating its meaning. Check two-digit marker alignment and continuation-line indentation.

Verify list semantics, nested reading order, marker visibility, long text, interactive descendants and the chosen productive/expressive type style.

## Practical transfer findings

A known author-written implementation probe using real `@carbon/react@1.117.0` was reviewed in an isolated browser fixture on 2026-09-29. These findings belong to that intermediate skill snapshot and generated fixture; they are not an exhaustive library audit or final-skill pass.

- Breadcrumb ancestor names and a named navigation region did not prevent placeholder `href="#"` destinations. Verify the actual navigation outcome, including fixture routes or real section targets.
- Passing `<h3>` as AccordionItem `title` put the heading inside the native button. Inspect the rendered hierarchy; use a supported toggle renderer forwarding the entire button contract when the task needs a heading containing the trigger. A heading in a source JSX expression is not proof of the correct DOM relationship.
- A ten-line CodeSnippet with `maxCollapsedNumberOfRows={9}` and the default minimum expanded rows showed Show more but returned to its collapsed state. Verify expanded height, visible lines and Show less after the control settles. Configure supported row limits against actual content; merely finding Show more is insufficient.
- An English command inherited page RTL, changing its visual ordering. Preserve the command's intended LTR direction in a scoped code region while mirroring surrounding layout; verify horizontal keyboard scrolling and exact copy text separately.
- A visible Remove button had no action handler. Review action-to-behavior wiring as well as the component's name, kind and keyboard affordance.
- Generated CSS referenced unresolved `~@ibm/plex` font URLs and the static server returned 404 for Sans/Mono assets. A successful Sass build and declared font-family did not load the intended face. Verify emitted URLs, copied/bundled font assets and actual browser requests before claiming Plex typography.
